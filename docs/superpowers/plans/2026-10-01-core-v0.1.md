# Core v0.1 (wrap-safe `WAITT`, wait-path timing, reference UART out of `src/`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. By the owner's instruction, all code in this plan is written by Opus/Sonnet implementer agents: the plan fixes the exact semantics, files, test names, expected values, mutants and commands; where a step says "write", the implementer writes it test-first.

**Goal:** `WAITT` stops stalling for a full timebase wrap when its deadline has already passed, the wait-completion path loses a 16-bit adder, and `src/` contains only files that are part of the hardened chip.

**Architecture:** One semantic change in the ISA (`WAITT Rn` completes when bit 15 of `(T − Rn)` is 0), mirrored in the Python oracle, the RTL and the formal properties, and exercised by directed tests, the differential fuzzer and a top-level pin test. Timed waits keep their equality compare. The design is `docs/superpowers/specs/2026-10-01-wrap-safe-deadline-design.md` — read it first.

**Tech Stack:** Verilog-2005 (Yosys/Icarus/Verilator), cocotb 2.0.1 + pytest 8.4.2 via `source env.sh`, project venv (`.venv`) for tools, SymbiYosys (`sby`), Tiny Tapeout cmos5l flow in GitHub Actions.

## Global Constraints

- Branch `core-v0.1` (off `main` at `778e8c0`). Agents never push, never merge, never touch `main`, never amend existing commits.
- All RTL is Verilog-2005 with `` `default_nettype none `` at the top of every file. Verilator lint must be clean: `verilator --lint-only -Wall -Wno-DECLFILENAME -Isrc src/*.v --top-module tt_um_abagel_coder_protocol_emulator`.

- No encoding change: `src/isa_defs.vh` stays byte-identical. Generated files (`docs/isa.md`, `tools/isa_defs.py`, `src/isa_defs.vh`) change only through `isa/isa.yaml` + `.venv/bin/python tools/gen_isa.py`; `.venv/bin/python tools/gen_isa.py --check` must exit 0.
- `WAITT` and `DELAY` leave `TO`, `Z`, `C` unchanged. Timed waits (`WAITP`, `WAITF`) keep the equality compare on the captured deadline; `Rt = R0` still means 65535 ticks; a timeout register holding 0 still completes in the first cycle.
- One branch delay slot; every non-wait instruction is exactly one cycle; `active = run_q && !halted && !core_reset`; `T` free-runs from reset. None of this changes.
- Suites that must pass, warning-free, before every commit: `.venv/bin/pytest -q`; `make -C test -B`; `make -C test -B -f Makefile.core`; `make -C test -B -f Makefile.blocks`; `make -C test -B -f Makefile.uartfw`; `cd formal && sby -f core.sby` (five tasks). `make` exits 0 even when a cocotb test fails: read the `TESTS= PASS= FAIL=` line.
- Every new or changed test and property is proven decisive: break exactly the behaviour it guards in a scratch copy of the repo (never in the checkout), show it fails there and passes on the real tree; record mutant, command and decisive output lines in the task report.
- `test/test_host.py` runs against the flattened gate-level netlist in CI: tests there use top-level pins only (no hierarchical references, no reads that can be X).

### Task 2: Wrap-safe `WAITT` and the simplified timeout completion

**Files:**
- Modify: `isa/isa.yaml` (regenerate `docs/isa.md`, `tools/isa_defs.py`), `tools/sim.py`, `src/pe_core.v` (logic at the wait unit and the `ifdef FORMAL` block), `formal/README.md`, `tests/test_sim.py`, `test/test_core.py`, `test/test_host.py`, `test/test_diff.py`, `docs/info.md`, `docs/superpowers/specs/2026-09-15-protocol-emulator-design.md` (status note only), `HANDOFF.md`, `README.md` (only where it states the old limitation)
- Test: the files above; `formal/core.sby` tasks

**Interfaces:**
- Consumes: Task 1's tree (no code dependency).
- Produces: the `WAITT` rule of the design doc §2 in ISA text, oracle and RTL; RTL logic differs from `778e8c0` in exactly two expressions (below) plus the `wdead` capture source.

**Exact semantics (from the design doc; these are requirements, not suggestions):**
- `WAITT Rn` completes in the first cycle in which bit 15 of the 16-bit difference `T − Rn` is 0. Equal → completes; deadline 1…32,768 ticks ahead → stalls, completes exactly when `T == Rn`; deadline 1…32,767 ticks behind → completes in its first cycle. Flags untouched. `WAITT R0` uses deadline 0.
- RTL: `waitt_done` is the complement of bit 15 of `t_in − rt_v`. `timed_to` becomes `wait_active ? (t_in == wdead) : (tmo == 16'd0)`. `wdead` is still captured as `t_in + tmo` when a timed wait starts. Nothing else in the logic changes.
- Oracle: `WAITT` completes when `((T − Rn) & 0xFFFF) < 0x8000`.

- [ ] **Step 1 (ISA text, test-first for the generator):** rewrite `semantics.waits` in `isa/isa.yaml` to state the new rule (the three cases, flags untouched, "keep deadlines less than 32,768 ticks ahead"), keeping every other sentence; regenerate; `gen_isa.py --check` exits 0; `git diff -- src/isa_defs.vh` is empty.
- [ ] **Step 2 (oracle, test-first):** in `tests/test_sim.py` write failing tests, then change `tools/sim.py`:
  - `test_waitt_late_deadline_completes_in_one_cycle`: deadlines 1, 300 and 32,767 ticks behind `T` each complete in exactly one cycle (construct `Rn` from `SETT` plus elapsed cycles or ALU arithmetic; assert the exact cycle of the first pin write after the `WAITT`).
  - `test_waitt_boundary_32768_ahead_waits_exactly`: a deadline exactly 32,768 ticks ahead completes exactly at `T == Rn` (32,768 ticks later), and one 32,769 ticks ahead completes in one cycle.
  - `test_waitt_leaves_to_unchanged`: with `TO = 1` (set by a timed-out `WAITF` with a small `Rt`) and with `TO = 0`, a late and an on-time `WAITT` both leave `TO` as it was (observe with `BTO`).
  - The existing `test_waitt_exact_and_no_drift` and `test_timebase_t0_wraparound_preserves_waitt_period` stay unchanged and green.
- [ ] **Step 3 (RTL, test-first):** in `test/test_core.py` write the same three cases as cocotb tests against the RTL (`waitt_late_deadline_completes_in_one_cycle`, `waitt_boundary_32768_ahead_waits_exactly`, `waitt_leaves_to_unchanged`), see them fail on the current RTL where the behaviour differs, then change `src/pe_core.v` as specified. The existing `waitt_no_drift` and `waitt_period_holds_across_T_wraparound` stay unchanged and green.
- [ ] **Step 4 (top level, gate-level safe):** in `test/test_host.py` add `run_low_across_deadline_resumes_immediately`: load a program that arms a deadline a few hundred ticks ahead and waits on it, drop the RUN pin while it is stalled, hold RUN low until `T` has passed the deadline, raise RUN, and assert the pin write after the `WAITT` appears within a small fixed number of cycles of the resume (state the exact number and derive it in a comment) and not before the resume. Pins only.
- [ ] **Step 5 (fuzzer):** `test/test_diff.py` generates `WAITT` (it was excluded only because a random deadline could stall 65,535 ticks): mostly right after a `SETT`/`ADDT` on the same register with a small positive offset, occasionally on an arbitrary register. Keep the module docstring's measured statistics accurate (how many `WAITT` words per run, how many stall, how many complete late) by measuring them. The suite's wall-clock must stay within about 20 % of its current value at the default program count; if a long stall would exceed the per-program budget both models simply stall together — say so in the docstring.
- [ ] **Step 6 (formal):** in the `ifdef FORMAL` block of `src/pe_core.v` restate the deadline theorem and add the lemmas, each stated on state and port signals (not as a copy of the `waitt_done` or `timed_to` wires), each guarded like its neighbours (`f_past_valid`, `$past(rst_n)`, `!$past(core_reset)`), and each proven by `sby -f core.sby prove`:
  - Exactness when stalled: a `WAITT` that was stalled in the previous cycle and completes now does so with `T == Rn`.
  - No late release for a reachable deadline: an active `WAITT` with `T == Rn` completes in that cycle.
  - Late deadline: an active `WAITT` in its first cycle whose difference `T − Rn` is in 0…32,767 completes in that cycle; in −32,768…−1 it does not.
  - `WAITT` completion leaves `{fto, fc, fz}` unchanged.
  - Equivalence of the simplified timeout completion: the new `timed_to` equals `t_in == (wait_active ? wdead : t_in + tmo)` in every state.
  - A cover: a `WAITT` that completes in its first cycle with a strictly positive difference (a genuinely late deadline), reached after reset.
  If a lemma needs a fact about the timebase (for example that `T` advances by at most one per cycle), use the fact already established in the harness or the timebase lemmas, and list it as a hypothesis in `formal/README.md` rather than assuming it silently. Update `formal/README.md`: theorem table, spec §6 mapping (property 1 is now proved for the wrap-safe rule), "What is NOT proved", mutant table, results and wall-clock.
