# Formal proofs (SymbiYosys)

Machine-checked proofs of the core's timing contract: `pe_core.v` (with `pe_gpio.v` and
`pe_timebase.v`) under `src/isa_defs.vh`. Properties live in the RTL itself, inside
`` `ifdef FORMAL `` blocks (see `src/pe_core.v` and `src/pe_gpio.v`, near `endmodule`), so they
cannot affect synthesis, simulation or lint -- `read_verilog -formal` is what defines `FORMAL`;
every other flow (Verilator lint, cocotb, LibreLane) never defines it.

## Setup

```
source ../env.sh    # OSS CAD Suite: sby, yosys, yices-smt2, boolector, z3, bitwuzla
cd formal
sby -f core.sby     # runs all three tasks below: bmc, prove, cover
```

Logs land in `formal/core_bmc/`, `formal/core_prove/`, `formal/core_cover/` (one directory per
task; `logfile.txt` has the full engine transcript, `engine_0/trace*.vcd` / `trace*.yw` hold any
counterexample or cover witness). These directories are gitignored and regenerated by `sby -f`.

`formal/core_props.v` is the proof harness: it instantiates `pe_timebase`, `pe_gpio` and
`pe_core` with the instruction stream, `ui_in`/`uio_in`, `prescale` and the host-side signals
(`h2c_valid`, `h2c_data`, `c2h_full`) all free (`(* anyseq *)` -- an arbitrary value every
cycle), and `rst_n` held low for cycle 0 only, then permanently high. This is deliberately more
permissive than the real chip (e.g. `imem_data` is free every cycle rather than a function of
`imem_addr`, and the timebase's `en` is tied to the free `run` rather than the real top level's
constant 1), so every property proved here also holds for every more-constrained real
environment.

## Theorems

- **T1_deadline_exact** (`src/pe_core.v`): whenever the core is `active` on a `WAITT`
  instruction, `adv == (t_in == rt_v)` -- it releases in exactly the cycle `T == Rn`, never
  earlier, never later.
- **T2_static_timing** (`src/pe_core.v`, two parts): (a) whenever `active` and the instruction
  is neither a `WAIT` (any sub-op) nor `HALT`, `adv` is 1 -- it completes in the cycle it is
  active, no hidden multi-cycle stalls. (b) whenever `adv` was 1 last cycle and no
  reset intervened, `pc` now equals last cycle's `next_pc` -- a completed instruction's chosen
  successor address is really what lands in `pc`.
- **T3_reset_safety** (`src/pe_gpio.v`): `uio_oe == 0` from reset until the first executed `OE`
  pin instruction -- no bidirectional pin ever drives before firmware says so.
- **T4_bounded_wait** (`src/pe_core.v`, structural; `formal/timebase_props.v`, supplementary):
  a timed wait (`WAITP`/`WAITF`/`WAITL`, i.e. any `WAIT` sub-op other than `WAITT`/`DELAY`)
  cannot stall more than 65536 ticks. Proved as two structural lemmas in `pe_core.v`: (i) once
  `wait_active` latches for a wait that does not complete this cycle, its deadline `wdead` is
  held constant until the wait completes; (ii) the wait completes (`adv`) in any cycle where
  `t_in == wdead`. See "T4's bound: what's proved vs. argued" below for how this becomes the
  65536-tick bound, and what the supplementary `formal/timebase.sby` proof adds.
- **T5_side_effects_only_when_active** (`src/pe_core.v`, two lemmas): `gpio_wr_en`,
  `gpio_pin_en`, `h2c_pop`, `c2h_push` are all 0 whenever `active` is 0 (covers halted, RUN low,
  and the `core_reset` cycle). Split into **T5a** (`active` really does equal
  `run_q && !halted && !core_reset`, the ISA's own `semantics.run` contract) and **T5b** (the
  four side-effect strobes are 0 whenever `active` is 0). See "Mutation testing" for why T5a
  exists.

## What's assumed

The *only* assumption in `core.sby` / `core_props.v` is the reset sequence built into the
wrapper: `rst_n` is low for cycle 0, then permanently high (never asserted again). Everything
else -- the instruction stream, all chip inputs, all host-interface signals -- is free every
cycle. No `assume` statements appear anywhere in `src/pe_core.v` or `src/pe_gpio.v`; every extra
property beyond the brief's original T1-T3 (T2b, the T4 structural lemmas, T5a, T5b) is an
`assert` (a proven lemma), never a weakened hypothesis.

The supplementary `formal/timebase.sby` / `formal/timebase_props.v` proof (T4's "counting part",
see below) additionally assumes `en` is tied to constant 1 and `prescale` is fixed to an
arbitrary-but-constant value (`(* anyconst *)`) for the whole trace -- this is the one place the
task brief permits an extra assumption ("the timebase configuration"). It is a separate,
supplementary proof, not part of `core.sby` / CI, and does not weaken T1-T5's own proofs (which
remain assumption-free beyond reset).

## T4's bound: what's proved vs. argued

The 65536-tick bound is the composition of three facts:

1. **(proved, `pe_core.v`, part of `core.sby`)** While a timed wait is outstanding and hasn't
   completed, its latched deadline `wdead` never changes.
2. **(proved, `pe_core.v`, part of `core.sby`)** The wait completes (`adv`) in any cycle where
   `t_in == wdead`.
3. **(proved, `formal/timebase_props.v`, supplementary, *not* part of `core.sby`/CI)** T
   (`t_out`) never skips a value -- each cycle it either holds or advances by exactly 1 -- and
   the timebase's internal tick period never exceeds the fixed `prescale`, so ticks cannot stall
   forever.

Facts 1+2 give: if T ever again equals the frozen `wdead`, the wait completes that cycle, and
that value can never be skipped over (fact 3's "no skip"). Since T is a free-running 16-bit
counter, it must revisit every value (in particular `wdead`) within one 65536-tick wrap. Fact
3's "ticks cannot stall forever" additionally rules out T freezing forever before completing
that wrap (which would need `en` to be held low forever by the environment -- ruled out by the
supplementary proof's `en = 1` assumption).

**We did prove the counting part** (fact 3), but as a *separate, supplementary* proof
(`formal/timebase.sby`), with `en` forced to 1 and `prescale` fixed via `(* anyconst *)`,
because it inherently needs an assumption (`en` held) that the main `core.sby` proof
deliberately does not make (there, `en` is free, so T could legitimately stop advancing forever
if the environment holds `run` low forever -- a real, if uninteresting, way to falsify a
liveness claim that has nothing to do with the core's own correctness). The composed 65536-tick
bound is stated here as an argument built from three independently machine-checked facts, not
as a single end-to-end formal property (SymbiYosys's BMC/k-induction prove safety invariants,
not liveness/eventuality directly; proving the full bound as one property would need a `mode
live` proof with fairness constraints on `en`, which was judged out of scope for a "cheap"
addition).

## Mutation testing

Sanity-checked that the proofs are not vacuously true by deliberately breaking the RTL in place
(`src/pe_core.v`), re-running `bmc`, then reverting to the exact `git diff`-clean state
(confirmed via `git diff --stat src/` showing only the `ifdef FORMAL` block insertions, and a
re-run of Verilator lint) before the next mutation and before the final commit. See the task
report for the full transcripts.

- **T1**: changed the `WAITT` release condition from `waitt_done = (t_in == rt_v)` to
  `(t_in == rt_v + 16'd1)`. `bmc` (depth 20, boolector) **fails at step 3** (~0.3s): with
  `rt_v == 0`, `adv` fires at `t_in == 1` instead of `t_in == 0`, violating
  `assert(adv == (t_in == rt_v))` (`pe_core.v:214`, T1_deadline_exact). Confirms T1 catches an
  off-by-one deadline.
- **T5**: removed `!core_reset` from `active`'s definition
  (`active = run_q && !halted && !core_reset` to `run_q && !halted`). This is where mutation
  testing earned its keep: with only the originally-specified T5 (now T5b) in place (T5a
  commented out), `bmc` at depth 20 **passed** (~10.6s, no counterexample) -- T5b is
  structurally a tautology, because `gpio_wr_en`, `gpio_pin_en`, `h2c_pop` and `c2h_push` are
  *all* defined as `active && ...`, so "if `!active` then these are 0" holds no matter how
  `active` itself is (mis)defined. We added **T5a**
  (`assert(active == (run_q && !halted && !core_reset))`) specifically to close this gap by
  independently re-deriving `active`'s intended formula; with T5a restored, re-running the same
  mutation **fails `bmc` at step 1** (~0.3s) on T5a (`pe_core.v:258`). T5a is what actually gives
  T5 its teeth against a regression in `active`'s own definition; T5b still matters for keeping
  every future side-effect signal honestly gated by (a now-verified-correct) `active`.

## Results

`core.sby` uses `smtbmc boolector` for all three tasks (yices-smt2 was tried first and did not
finish `bmc`/`prove` within 5 minutes at any reasonable depth on this properties/design size;
boolector closes the same properties in seconds -- see "Solver notes" below).
`formal/timebase.sby` uses boolector for `bmc` and yices for `prove` (boolector's k-induction
countdown search stalled past 9 minutes on the 300-depth, 8-bit-counter induction search where
yices closes in ~37s -- also below). Depth and wall-clock time (`sby`'s own "Elapsed clock
time") per task, from the final clean run (`git diff --stat src/` showing only the `ifdef
FORMAL` blocks):

| Task (`core.sby`) | Mode | Engine | Depth | Result | Wall time | Notes |
|---|---|---|---|---|---|---|
| `bmc`   | BMC | boolector | 20 | PASS | 10s | no assertion violated through step 19 |
| `prove` | k-induction | boolector | 8 (bound) | PASS | <1s | induction closed at step 5 |
| `cover` | cover | boolector | 20 (bound) | PASS (5/5 goals) | <1s | all 5 goals reached by step 5 |

| Task (`formal/timebase.sby`, supplementary) | Mode | Engine | Depth | Result | Wall time | Notes |
|---|---|---|---|---|---|---|
| `bmc`   | BMC | boolector | 40 (bound) | PASS | <1s | no assertion violated through step 39 |
| `prove` | k-induction | yices | 300 (bound) | PASS | 37s | induction closed at step 43 |

"Depth" for `prove` is the search bound sby was given (`prove: depth N`); k-induction itself
reports the actual step at which the induction check succeeded, which is what makes each of
these an *unbounded* proof (valid for all step counts, not just up to the bound) rather than a
bounded one -- noted in "Notes" above. `bmc` depth is a true bound: it is a proof of no
counterexample within that many steps, not an unbounded proof, and is reported as such.

`cover` reached all 5 cover goals: a `WAITT` that stalls then releases, a timed wait that
completes via timeout (not via its condition), a taken branch immediately followed by its
delay-slot instruction executing, an `OE` pin instruction executing, and (in `pe_gpio.v`) that
same `OE` execution actually setting `uio_oe` away from all-zero.

### Solver notes

The properties in `core_props.v` are all one- or two-cycle local relations (T1/T2/T4/T5 relate
`active`/`adv` in the current cycle, or the current cycle to `$past(...)`; T3 is a single-cycle
invariant) over a fully free (`anyseq`) instruction stream, so k-induction should close --  and
does close, at step 5 -- at a small depth. In practice `yices-smt2` took over 5 minutes and had
not finished `bmc`/`prove` even at step ~22 out of 40/24 in an earlier attempt at this same
property set (superseded by this run); switching the engine to `boolector` and lowering the
configured depths to the guidance-recommended range (`bmc` 20, `prove` 8) brought both tasks
under 11s combined. The opposite held for `formal/timebase_props.v`'s `prove` task: its
induction search (300-depth bound, `since_tick <= prescale` over an 8-bit counter) ran past 9
minutes under boolector without finishing and was killed, while `yices-smt2` closes it in ~37s
(induction succeeds at step 43) -- this is the same task that needed depth 300 documented below,
now confirmed fast with the right solver. `formal/timebase.sby`'s `[engines]` section therefore
picks the engine per-task (`bmc: smtbmc boolector`, `prove: smtbmc yices`).

(`timebase.sby`'s `prove` bound is 300, not 8: an 8-bit counter admits k-induction starting
states past `prescale` that need up to a full 256-cycle wrap to resynchronize -- unrelated to
`core.sby`'s properties, which are genuinely 1-2 cycle local and close at step 5.)

`.superpowers/sdd/task-9-report.md`.
